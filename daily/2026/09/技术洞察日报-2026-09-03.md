### 1、Prefix Sliding用有界上下文重塑长程推理成本 {#event-33860}

【AI推理与服务加速】 【Prefix Sliding】 【KV cache】 【性能提升】

📋 **要点**：2026-09-02，相关文章围绕**Prefix Sliding**讨论长程推理中token冗余的问题：在full attention下，推理链越长，**KV cache**和计算成本越高，而注意力可视化显示中间token往往很快失去作用。作者因此提出只保留前缀和滑动窗口的机制，并说明可通过Continue PE、分块回传和自定义kernel把该方法用于推理与训练，目标是在不重训现有模型的前提下实现更长轨迹和更高吞吐。
📌 **总结**：这一思路对长上下文产品、Agent编排和推理系统的意义在于，它给出了一个可以直接迁移到现有模型上的成本上限方案，而不是要求从头换架构。若后续工程化成熟，团队在规划上下文预算、缓存策略和长链路任务时，便能按“有界成本”而不是“线性膨胀”来设计系统。

### 2、NVIDIA用投机解码压低LLM推理开销 {#event-33350}

【AI推理与服务加速】 【speculative decoding】 【TensorRT-LLM】 【性能提升】

📋 **要点**：2026年9月2日，**NVIDIA**围绕 **speculative decoding** 给出一套面向 **LLM** inference 的共设计方法，核心是在解码阶段用小 draft model 先生成多 token，再由大 target model 一次并行校验，从而减少逐 token 迭代次数。文章进一步比较 external draft model、**MTP**、**EAGLE-3**、**DFlash**、**DSpark** 与 suffix/n-gram 等机制，并用 **SPEED-Bench** 和 **TensorRT-LLM** 说明应如何结合 workload、draft length、acceptance length 与 draft overhead 选择最优配置。
📌 **总结**：这类方法的价值不在于单点提速，而在于把推理加速从“模型越大越慢”的粗粒度判断，推进到围绕 token 接受率、KV cache 压力、kernel tile 对齐和训练/部署成本的系统优化。对推理平台与芯片方案设计而言，它提供了可复用的调参框架，也强化了模型结构、serving 架构和硬件执行效率之间的联动判断。
来源：[NVIDIA](https://developer.nvidia.com/blog/co-designing-ai-models-using-speculative-decoding-for-faster-llm-inference/)

### 5、CNY让图邻域探索进入推理过程 {#event-32494}

📋 **要点**：该论文面向 text-attributed graphs 的推理任务，指出既有方法通常先固定可访问邻居集合，再在静态上下文上生成，难以在推理过程中补充缺失证据。**CNY** 通过 topology-constrained **graph-walk** actions 让 **LLM** 主动查看轻量邻居预览，并在需要时继续扩展候选邻居；同时引入 destination-conditioned on-policy self-distillation，把已选邻居在内容展开后的变化转化为动作级训练信号，从而缓解延迟信用分配问题。
📌 **总结**：这类方法把图推理的关键能力从一次性上下文拼装，推进到可执行的探索式 reasoning，对知识图谱问答、检索增强推理和图上 agent 设计都有借鉴意义。其价值在于让模型在证据不完整时仍能继续“找证据”，减少被静态上下文锁死的风险，也为图搜索与推理一体化提供了更明确的训练路径。
来源：[研究团队](https://arxiv.org/abs/2608.29588)

### 1、微软滑动窗口让线性注意力失去优势 {#event-31544}

【AI推理与服务加速】 【Sliding Window Attention】 【attention sinks】 【性能提升】

📋 **要点**：2026年9月，微软团队把 **Sliding Window Attention** 与多种线性注意力改造方案放到同一基准下比较，核心做法是在不改权重、不过后训练的前提下，为窗口保留 4 个 **attention sinks**，并在多个模型系列与知识、推理、长上下文任务上验证效果；结果显示，该方法在六项任务上的平均性能恢复率达到 **99.0%**，且在较长上下文下仍能保持较好的吞吐和更稳定的推理状态。
📌 **总结**：这项结果对推理架构的价值在于，它把“降低 KV **Cache**”这件事从复杂的模型重构，拉回到更容易落地的工程基线选择。对研发团队来说，先尝试带 sinks 的 **SWA** 可能比投入数亿 token 做线性化后训练更省算力、更快验证；对产品架构来说，也意味着现成大模型可以用更小的状态成本部署到长上下文场景，减少对激进结构改造的依赖。

### 2、单卡压缩把70B模型跑进33GB内存 {#event-32943}

【AI推理与服务加速】 【单卡推理】 【KV-cache】 【成本下降】

📋 **要点**：这项研究把 **70B** 参数模型的单 **GPU** 部署拆成显存、长上下文吞吐和工程集成成本三个预算维度，系统评估 pruning、quantization 与 **KV-cache** compression 的耦合关系。作者发现，层级剪枝能提升权重量化鲁棒性，**KV-cache** 稀疏化可以与 **INT8 KV** 量化互补，在不伤解码速度的情况下减少内存，而静态向量量化又常与动态缓存冲突。基于这些结果，论文整理出一条实用流水线：将 **70B** 模型压到约 **33 GB**，在单张 **A40** 上对 10k token 提示维持约 **57 token**s/s，且常识和推理基准的绝对精度损失控制在 **5%** 以内。
📌 **总结**：这项工作对**单卡推理**部署的意义在于，它不是只报一个压缩率，而是把质量、内存和端到端速度放在同一预算框架下比较，方便工程团队做真实取舍。对技术路线而言，它强化了“剪枝+量化+KV 缓存压缩”联动设计的可行性，也说明大模型上单卡运行并非只能依赖单一技巧，而应围绕预算约束做组合优化。
来源：[研究团队](https://arxiv.org/abs/2608.30076)
原文标题：Budget-Aware Compression Pipeline for Single-GPU LLM Inference: Methods, Trade-offs, and Coupling Effects

### 3、韩俊霖团队用受控实验重写多模态预训练配方 {#event-34035}

【模型评测】 【Ideation Arena】 【研究创意】 【体验提升】

📋 **要点**：2026-08-30 这项工作提出 **Ideation Arena**，用 battle style 的双盲 pairwise assessment 评估 **LLM** 生成的**研究创意**；作者让 105 名活跃计算机科学研究者对 14 个 frontier **LLM** 和 5 种基于 2 个底座模型构建的 research agent 进行 6,000 多次比较，并在共享文献上下文下构建 **Elo** leaderboard，同时验证自动评估器仍难以稳定复现专家偏好。
📌 **总结**：这项工作把研究 idea 生成从“能不能想出来”推进到“能不能被专家稳定喜欢”的层面，对研究型智能体、agentic ideation 和自动评审系统都很关键。对技术路线的影响在于，未来创意生成系统不仅要优化文本质量，还要围绕人类偏好、上下文共享和排行榜机制做产品化设计。
来源：[研究团队](https://arxiv.org/abs/2608.29696)
原文标题：Ideation Arena: Evaluating LLM Generated Research Ideas with Battle-style Human Expert Assessment

## AI安全、可信与治理

### 1、Meta-adaptive 攻击暴露视觉语言模型新型越狱面 {#event-30943}

【AI安全、可信与治理】 【视觉语言模型】 【jailbreak】 【安全风险】

📋 **要点**：2026年8月27日，论文指出现有**视觉语言模型**越狱攻击多停留在模板或迭代内容层面，而新的 **MAMJ** 方法进一步把攻击者本身纳入优化对象，同时调整攻击策略提示与攻击者权重。作者用 **LLM** 评审先修正攻击策略，再以组级 **ASR** 奖励更新攻击参数，在 **MM-SafetyBench** 上分别对 **GPT-4o**、**Gemini-3-Pro-Preview** 和 **Seed 2.0** 获得较高攻击成功率，并能迁移到未见过的目标模型。
📌 **总结**：这说明前沿 **VLM** 的安全边界并不只取决于单轮提示过滤，而是会受到更高层级的自适应攻击影响。对安全与治理路线的影响，是防御机制需要考虑攻击策略迭代、跨模型迁移和元学习式攻击者；对产品和平台的影响，是视觉语言系统不能只靠静态规则，必须引入更强的红队评测、持续监测和针对性加固。
来源：[研究团队](https://arxiv.org/abs/2608.27531)
原文标题：Fully Unleashing the Multimodal Attacker: Meta-Adaptive Jailbreaking of Vision-Language Models

### 2、CamoDocs 以伪装文档绕过 RAG 投毒防线 {#event-30837}

【AI安全、可信与治理】 【RAG投毒】 【伪装文档】 【安全风险】

📋 **要点**：2026年8月28日，论文针对 retrieval-augmented generation 的文档投毒问题提出 **CamoDocs**，方法是不直接把目标查询写进恶意文档，而是把合成的 benign 与 adversarial 内容切块后混入正常文本，再用分散 token 和一致性过滤降低可检测特征。作者在七种 **RAG** 防御、三种开源模型和多个基准上验证了该方法，结果显示它仍能维持较强攻击成功率，并对 **GPT-5.4-mini** 和 **Claude-Haiku-4.5** 也有有效性。
📌 **总结**：这表明 **RAG** 的风险不只来自提示注入，也来自检索语料本身的伪装式污染。对技术路线的影响，是检索增强产品不能只做关键词或向量层过滤，还要把文档来源、聚类去噪、可疑内容检测和效用损失一起纳入防线；对架构判断的影响，是公共知识库、用户可编辑源和外部抓取源都应视为高风险输入面。
来源：[研究团队](https://arxiv.org/abs/2608.28389)
原文标题：CamoDocs: A Poisoning Attack Against Retrieval-Augmented Language Models Using Camouflaged Documents

## AI模型

### 1、H3-World 用 LoRA 把语言理解接到可控世界生成 {#event-34397}

【AI模型】 【H3-World】 【MiniMax-H3】 【性能提升】

📋 **要点**：2026-09-01，**DANNY621/H3-World** 在 **Hugging Face** 公布基于 **MiniMax-H3** 的互动世界模型，输入初始帧和键盘控制后，可生成动作可控的视频序列；项目通过将键盘状态映射为未来视频潜变量的语言指令，并用 directed attention routing 把每条指令绑定到对应时间区间，同时使用 8,000 段 gameplay clips 训练出 65.6M **LoRA** 参数，只占 **33B** 主干参数的 **0.199%**。
📌 **总结**：这类做法把世界模型的控制接口从纯文本扩展到动作驱动的时序生成，说明大参数底座并不一定要全量改造，**LoRA** 加路由补丁就能形成较低成本的领域适配路径。对技术路线而言，它强化了“底座模型 + 轻量控制层 + 场景数据”的组合思路；对产品侧，则意味着交互仿真、游戏控制和可控生成可以围绕同一底层能力复用。
来源：[Hugging Face Models](https://huggingface.co/DANNY621/H3-World)
原文标题：DANNY621/H3-World · Hugging Face

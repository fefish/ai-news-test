1、AWS Agent Registry正式商用，统一治理企业智能体资产

智能体平台、协议与执行系统 AWS Agent Registry MCP服务器 研发效率提升

📋 要点：2026年8月31日，AWS宣布Agent Registry正式商用，面向企业内部智能体、工具、技能、MCP服务器及自定义资源提供私有目录和统一发现层。平台支持语义与关键词搜索、审批工作流、CloudTrail审计，并可通过CloudFormation、Terraform和AWS CDK进行基础设施即代码管理；借助AWS RAM可跨账户共享注册表，还能自动发现组织内AgentCore运行时和网关中的智能体资源，并向开发环境暴露MCP服务接口。

📌 总结：Agent Registry将企业智能体建设中的资产发现、准入审批、访问控制、成本归属和审计追踪收敛到统一控制面，可降低团队重复开发与人工登记成本，并提高智能体和工具跨团队复用效率。其与AgentCore、Amazon Quick及Kiro IDE的联动，表明云厂商正把智能体目录、运行时和开发入口整合为平台级体系；设备供应商建设内部Agent平台时，需要同步评估目录元数据、跨账户治理、自动发现和MCP兼容能力。

📋 要点：2026年8月27日，Cisco 开始向全球约 9 万名员工部署个人 AI Agent MyAgent，并将其定位为从 chat-based interaction 走向 supervised autonomous execution 的企业级执行入口。文章披露，MyAgent 建立在 Cisco 内部平台 Circuit 之上，支持持久记忆、意图驱动、跨系统执行、后台运行、个人化权限和子 Agent 调用，并可通过 Agent Registry 与 MCP Registry 接入受审查的连接器和专业 Agent。Cisco 还说明，平台会根据任务类型、成本、延迟、可靠性和模型能力进行动态路由，尽量把确定性任务交给自动化系统，把复杂推理留给更强模型。

1、llm-d重构多模态请求调度，十六张H200吞吐提升44%

AI推理与服务加速 llm-d多模态服务 内容哈希路由 性能提升

📋 要点：2026年8月31日，开源推理项目llm-d说明其面向规模化多模态服务的系统设计：由于图像需经视觉编码器转化为token，多模态请求在负载大小、计算成本、首token时延、缓存身份和处理阶段上均不同于纯文本请求，沿用文本调度参数容易造成资源判断失真。llm-d为此引入媒体token估算、基于内容哈希的路由、重新调节的亲和门限和独立编码层，并以vLLM作为单副本模型服务器；其披露的16张H200测试结果显示，在每秒5至40个请求的负载阶梯中，p90首token时延保持亚秒级，吞吐量较轮询调度提高44%。

📌 总结：该方案将多模态服务优化从模型服务器内部扩展到跨副本调度与分阶段资源编排，说明图像编码成本、缓存复用和负载差异需要成为控制平面的显式输入。对推理平台架构而言，可据此评估编码与prefill、decode资源是否需要解耦，以及内容感知路由能否减少重复计算并改善尾时延；对研发团队而言，llm-d提供了可复用的开源实现和具有硬件规模、负载区间的性能证据。不过现有44%增益来自项目方特定16张H200测试，迁移到其他模型、媒体比例和加速器前仍需独立复测。

2、ZipTok3D把3D几何压缩到更短token前缀

AI模型 ZipTok3D 3D tokenization 架构替代

📋 要点：2026年9月，浙江大学团队提出 ZipTok3D，针对3D 生成中 token 序列过长、极低 token 预算下重建质量快速下滑的问题，先用 nested dropout 训练编码器，让保留下来的前缀必须独立恢复完整对象，再用参数共享的 Transformer block 反复解码这些前缀，从而把几何信息压进更短的全局 token 表示。

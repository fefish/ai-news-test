📋 **要点**：研究在不训练、不针对基准调参的条件下，仅比较同一模型单次回答与共享文件系统上的主管—工作者脚手架，覆盖九个模型及**LiveCodeBench**最新100道难题。**Qwen3.8-**2**7B**提升23.4分，**GPT-5.6-**Luna提升10.6分、Terra提升8.0分，**Kimi-**K3和Minimax-M3在关闭推理时分别提升30.4和11分；**Qwen3.6-**3**5B**则下降1至9分。主管机制约使token账单增至三倍，但Terra加主管以每轮11.71美元取得85.0分，接近Fable 5单次调用87.4分及61.11美元成本；转录分析将收益主要归因于上下文整理和问题分解。

### 2、LocalLSTC以长短期控制状态缩小本地GUI Agent能力落差 {#event-27934}

【智能体平台、协议与执行系统】 【LocalLSTC】 【持久执行状态】 【架构替代】

📋 **要点**：研究指出，**GUI** Agent通常把任务阶段、已获证据和运行反馈隐含在不断增长的交互轨迹中，较弱的本地模型每一步都要重新推断控制状态。四个代表性框架中，以Qwen3.5-**9B**替换GPT-5后，**OSWorld SR-**100均值从**60.9%**降至**37.7%**，且**91.6%**的失败轨迹至少出现一次控制故障。**LocalLSTC**无需训练，通过长期控制保存子目标、证据和反馈，再由短期执行形成有限承诺，并把执行结果回写持久状态。
📌 **总结**：**LocalLSTC**说明本地GUI Agent的落差并非只能靠更大模型弥补，显式的长期状态、短期承诺和双向反馈也可承担部分控制推理。对需要私有部署或控制API成本的企业桌面Agent，这种模型无关、免训练架构有助于把模型选择与执行控制解耦，并降低敏感操作依赖云端模型的程度。论文摘要未给出**LocalLSTC**最终提升数字，落地前仍需验证其状态一致性、错误累积和跨应用泛化。
来源：[研究团队](https://arxiv.org/abs/2608.25777)
原文标题：LocalLSTC: A Long Short-Term Control Architecture for Locally Deployed GUI Agents

### 3、PACE用两阶段证据检索将长视频问答准确率提升至42.6% {#event-27765}

【智能体平台、协议与执行系统】 【PACE】 【长视频证据检索】 【性能提升】

📋 **要点**：论文针对长视频问答中相关证据稀疏、普通相关线索难以区分相近答案的问题，提出**PACE**两阶段框架：第一阶段不查看候选答案，依据问题生成的因素索引片段级描述；第二阶段读取候选答案，构造对比线索并查询索引完成验证。使用开源Qwen3-VL骨干时，**PACE**在MMR-V上取得**42.6%**准确率，并在诊断子集找回**66.9%**的人工标注线索，超过直接推理和DVD等智能体基线。输入未提供作者机构。
📌 **总结**：该工作将长视频理解从泛化的“找到相关内容”推进到“找到能排除错误选项的证据”，对视频巡检、会议检索和多媒体故障分析具有方法价值。两阶段设计也便于记录证据链、限制无关上下文并提高回答可审计性；不过**42.6%**的总体准确率仍显示任务远未解决，实际产品需评估索引成本、候选答案依赖、开放问答适用性及长视频处理时延，不能仅凭相对领先投入生产。
来源：[研究团队](https://arxiv.org/abs/2608.26355)
原文标题：Finding the Right Evidence: Factor-Guided Coarse-to-Fine Reasoning for Long Videos

### 4、BTS-AgentBench把只读遥测编译为可重放智能体任务，验证构建确定性 {#event-28191}

【智能体平台、协议与执行系统】 【BTS-AgentBench】 【只读遥测回放】 【研发效率提升】

📋 **要点**：工业现场虽积累大量只读遥测，却缺少将原始记录系统编译为可执行多轮Agent任务的方法。**BTS-AgentBench**先规范化BTS元数据及历史记录，构建只读工具存储，再生成带工具推导标准答案和证据的静态任务，并提升为有类型、边界明确的操作员场景。532条发布数据加入澄清、目标修订、时间戳策略、质量门控和证据归因；两次独立构建完全复现11项逻辑导出及356/87/89划分。
📌 **总结**：该工作对网络运维Agent具有较强迁移价值：可把现网只读遥测转成带金标准、证据链和回放报告的任务，支持工具调用、澄清、目标变化及时间策略的稳定回归测试。其控制器在532条构建任务上完成0条，反而证明受限控制器未越权代做；另一路径在XAI4HEAT生成204个episode并完成测试。落地核心网前仍需替换BTS工具契约、网元语义和权限模型。
来源：[研究团队](https://arxiv.org/abs/2608.27334)
原文标题：BTS-AgentBench: A Deterministic, Replayable Pipeline from Read-Only Telemetry Logs to Agent Benchmarks

### 5、Google Cloud推出Cloud Run instances，为长驻单用户Agent提供专属运行时 {#event-26408}

【智能体平台、协议与执行系统】 【Cloud Run instances】 【长驻单例运行时】 【运维效率提升】

📋 **要点**：**Google** Cloud在2026年8月推出**Cloud **Run** instances**，面向持续运行、有状态且通常只服务单个用户的AI Agent工作负载，例如OpenClaw和Hermes。传统Cloud **Run** services会在无请求时缩容至零，不适合期望始终只有一个副本运行的长驻Agent；专用虚拟机则需要全天付费并自行维护操作系统、防火墙和HTTPS。新实例提供专属单例计算运行时，不自动扩缩容，可连续运行最长7天，默认配置自动重启，并提供跨更新和重启保持不变的HTTPS地址。

### 1、Ornith以自生成任务和脚手架闭环提升编码智能体评测成绩 {#event-29076}

【模型训练】 【Ornith 1.5】 【自生成训练任务】 【研发效率提升】

### 1、斯坦福联合华盛顿大学提出Prefix Sliding，裁剪中间Token使长推理最高提速约3倍 {#event-28742}

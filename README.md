# ai-news-test


| 使用场景            | 目标                                        |
| ------------------- | ------------------------------------------- |
| 每天看日报          | 快速知道过去 24 小时发生了什么              |
| 每周看周报          | 15 分钟讲清楚本周各板块趋势                 |
| 领导/专家点“感兴趣” | 收集业务关注点                              |
| 一键生成快报        | 快速说明某个热点与我们的关系                |
| 进入专项            | 支撑产品线、架构、规划、预研、PoC、专利输入 |

所以平台的第一验收标准不是“抓了多少源”，而是：

```text
信息有没有来源？
有没有分类？
有没有去重？
有没有标签？
有没有日报？
周报是不是趋势总结？
有没有人点击、评论、感兴趣？
有没有热点能转成快报？
有没有快报能进入专项？
有没有最终进入产品线或规划输入？
```

# 2. 系统总体架构调整

我建议系统调整为下面这个闭环。

```text
信息源台账
   ↓
多路线接入：RSS / API / 爬虫 / OpenClaw Skill / AI情报官 / 人工导入
   ↓
抓取与清洗
   ↓
去重与事件聚类
   ↓
打标签与板块分类
   ↓
信息可信度与源质量评估
   ↓
日报生成
   ↓
用户点击 / 点赞 / 感兴趣 / 评论 / 指派责任人
   ↓
周报趋势总结
   ↓
一键快报
   ↓
专项研究
   ↓
产品线 / 架构 / 规划 / 标准 / 专利 / PoC 输入
```

更具体一点：

```text
┌────────────────────────────┐
│ 1. 信息源管理 Source Hub     │
└─────────────┬──────────────┘
              ↓
┌────────────────────────────┐
│ 2. 接入层 Ingestion Layer    │
│ RSS / API / Crawler / Skill │
└─────────────┬──────────────┘
              ↓
┌────────────────────────────┐
│ 3. 内容处理 Content Engine   │
│ 清洗 / 去重 / 聚类 / 翻译     │
└─────────────┬──────────────┘
              ↓
┌────────────────────────────┐
│ 4. 智能分析 Intelligence     │
│ 打标 / 摘要 / 相关性 / 趋势   │
└─────────────┬──────────────┘
              ↓
┌────────────────────────────┐
│ 5. 展示与互动 Portal         │
│ 日报 / 周报 / 评论 / 点赞     │
└─────────────┬──────────────┘
              ↓
┌────────────────────────────┐
│ 6. 洞察闭环 Insight Loop     │
│ 快报 / 专项 / 责任人 / 例会   │
└────────────────────────────┘
```
